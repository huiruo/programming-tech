### 1.dom元素的高度和盒模型

先理解盒模型结构（从内到外）：
```
┌─────────────────────────────┐ ← Border 外边缘
│  Border（边框）              │
│  ┌───────────────────────┐  │ ← Padding 内边缘
│  │ Padding（内边距）      │  │
│  │  ┌─────────────────┐  │  │ ← Content 边缘
│  │  │ Content（内容） │  │  │
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
         ↑ Margin 在 Border 外面，不影响这三个高度
```

## box-sizing
`box-sizing` 决定你写的 `width/height` 计算的是哪一部分。

### 两种盒模型怎么“算宽度”

- `box-sizing: content-box`（默认，标准盒模型）
  - 你写的 `width` 只包含 **content（内容区）**
  - 元素最终占位宽度 = `width + padding-left/right + border-left/right`
- `box-sizing: border-box`（常说的 IE 盒模型）
  - 你写的 `width` 包含 **content + padding + border**
  - 元素最终占位宽度 = `width`

用一组具体数字建立直觉（`width: 200px; padding: 15px; border: 10px`）：

| box-sizing | 你写的 width 算什么 | 最终占位宽度 | 内容区宽度 |
|---|---|---|---|
| `content-box` | 只算内容区 | `200 + 15*2 + 10*2 = 250px` | `200px` |
| `border-box` | content + padding + border | `200px` | `200 - 15*2 - 10*2 = 150px` |

### 使用场景

**1）想固定“内容区”宽度时：用 `content-box` (默认，标准盒模型)（少见但合理）**

例如排版型页面希望“正文内容”永远是 600px，padding 只是额外留白；这时 `content-box` 更符合“固定内容宽度”的诉求（但需要你接受最终占位会变大）。

**2）做布局/组件时：优先 `border-box`（最常见）**

原因：你写的 `width` 就是元素在页面上“占多少空间”。加了 padding/border 也不会把盒子撑大，能减少溢出、换行、对不齐等问题（栅格、两列布局、卡片、表单输入框都很典型）。

常见的全局写法（很多项目默认就这么做）：

```css
/* 推荐：全局统一为 border-box，避免“算宽度” */
*, *::before, *::after {
  box-sizing: border-box;
}
```

### 一个更直观的对比例子

```html
<style>
.wrap { width: 400px; border: 1px solid #ccc; display: flex; gap: 10px; }
.item { width: 50%; padding: 20px; border: 2px solid #333; }
.contentBox { box-sizing: content-box; } /* 50% + padding + border => 很容易溢出/换行 */
.borderBox { box-sizing: border-box; }   /* 50% 包含 padding/border => 不会撑破布局 */
</style>
<div class="wrap">
  <div class="item contentBox">content-box</div>
  <div class="item borderBox">border-box</div>
</div>
```

补充：上面表格里算出来的 `150px` 是 **内容区高度/宽度（content box）**，不是 `line-height`（行高由 `line-height` 属性决定，跟盒模型是两回事）。

**三个高度的区别：**

| 属性 | 包含什么 | 用途 |
|-----|---------|-----|
| `offsetHeight` | content + padding + border | 元素"盒子"的总高度（你看到的整个元素） |
| `clientHeight` | content + padding | 元素"可视区域"的高度（去掉边框） |
| `scrollHeight` | content + padding + 溢出部分 | 元素"内容的真实总高度"（包括隐藏部分） |
| `scrollTop` | 滚动距离 | 滚动条滚动了多少（可读写） |

**举个实际例子：**

```html
<style>
.box {
  height: 100px;      /* 内容高度 */
  padding: 10px;      /* 上下各10px */
  border: 5px;        /* 上下各5px */
  overflow: auto;     /* 内容溢出时可滚动 */
}
/* 假设里面放了 300px 高的内容 */
</style>
```

计算结果：
```
offsetHeight = 100 + 10*2 + 5*2 = 130px  （盒子高度）
clientHeight = 100 + 10*2     = 120px  （可视区域，不含边框）
scrollHeight = 300 + 10*2     = 320px  （内容总高度，含溢出部分）
```

**什么时候用哪个？**

- `offsetHeight`：想知道元素在页面占多大空间
- `clientHeight`：想知道元素可视区域有多大（滚动容器时用）
- `scrollHeight`：想知道滚动容器里内容总高度（判断是否滚动到底部）

### scrollTop：滚动距离

**scrollTop = 滚动条滚动了多少距离**

```
滚动前（scrollTop = 0）：
┌─────────────┐ ← 可视区域顶部
│ 内容 A      │
│ 内容 B      │
│ 内容 C      │  ← 可视区域（clientHeight）
└─────────────┘ ← 可视区域底部
│ 内容 D      │  ← 滚动后被看到
│ 内容 E      │
│ 内容 F      │

向下滚动后（scrollTop = 50）：
│ 内容 A      │  ← 滚上去看不到了
│ 内容 B      │
┌─────────────┐ ← 可视区域顶部
│ 内容 C      │
│ 内容 D      │
│ 内容 E      │  ← 可视区域
└─────────────┘ ← 可视区域底部
│ 内容 F      │
```

**判断是否滚动到底部：**

```js
// 滚动到底部的条件
scrollTop + clientHeight >= scrollHeight

// 为什么用 clientHeight 而不是 offsetHeight？
// - clientHeight = 内容可视区域（不含 border）
// - offsetHeight = 盒子总高度（含 border）
// - 滚动发生在"内容区域"，border 不参与滚动计算
// - scrollTop 是基于内容区域计算的，不包括 border
// - 如果用 offsetHeight，会把 border 加进去，导致判断不准确
//   例如：border=5px 时，会提前5px判断为"到底了"

// 理解：
// scrollTop（已滚动距离） + clientHeight（可视区域） = 当前看到的位置
// scrollHeight（内容总高度） = 底部位置
// 当两个相等时，说明到底了
```

**实际应用示例：**

```js
const box = document.querySelector('.scroll-box');

// 监听滚动
box.addEventListener('scroll', () => {
  const scrollTop = box.scrollTop;           // 滚动了多少
  const clientHeight = box.clientHeight;     // 可视区域高度
  const scrollHeight = box.scrollHeight;     // 内容总高度

  // 判断是否到底
  if (scrollTop + clientHeight >= scrollHeight) {
    console.log('已滚动到底部，可以加载更多');
  }
});
```

## css中隐藏元素
* diaplay: none; --> 盒模型不生成，被隐藏的元素不占据任何空间,其占用的空间会被其他元素所占有，从而会引起浏览器的重排和重绘。
>v-show： 调用display:none 来控制元素,display:none；视觉上消失，也不占位置，但Dom节点还在。
* visibility: hidden; --> 如同opacity属性，被隐藏的元素依然会对我们的网页布局起作用。与opacity唯一不同的是它不会响应任何用户交互。(导致浏览器的重绘而不会引起重排)
>视觉上消失，但是还占着位置。 
* opacity: 0; --> 元素本身依然占据它自己的位置并对网页的布局起作用，它也将响应用户交互。
* v-if ：让Dom节点直接消失。（即：视觉上看不到，也没有位置，dom节点也不在。）

### css优先级：
- 第一优先级：!important
- 1.内联样式，如style="color: green"，权值为1000
- 2.ID选择器，如#app，权值为0100
- 3.类、伪类、属性选择器，如.foo, :first-child, div[class="foo"]，权值为0010
- 4.标签、伪元素选择器，如div::first-line，权值为0001
- 5.通配符、子类选择器、兄弟选择器，如*, >, +，权值为0000
- 6.继承的样式没有权值

		- 2.宽高:

			块级可设置高度
		- 2.行内元素的display属性默认为inline 
2. 块级元素：行内标签转换为块级标签：display:block;

## BFC（块级格式化上下文）

### 什么是 BFC？

简单理解：**BFC 就是一个"封闭的盒子"，盒子里的元素和外面的元素互不影响。**

类比：想象一个密封的房间，房间里的人怎么活动都不会影响房间外面的人，外面的人也进不来。

**⚠️ 重要：普通 `<div>` 默认没有 BFC！需要主动触发。**

```html
<!-- 这个 div 没有 BFC，是"开放的"，会有浮动塌陷、margin重叠等问题 -->
<div class="parent">
  <div class="child">内容</div>
</div>
```

### 触发 BFC 的条件（让元素变成"封闭盒子"）

常用方式：
```css
overflow: hidden;      /* 最常用 */
display: flow-root;    /* 新语法，专门创建 BFC */
display: flex / grid;  /* Flex/Grid 容器自带 BFC */
position: absolute;    /* 绝对定位元素 */
float: left/right;     /* 浮动元素 */
```

### BFC 解决的 3 个实际问题

#### 问题1：子元素浮动，父元素高度塌陷

```html
<!-- 问题：父元素高度为 0 -->
<style>
.parent {
  border: 2px solid red;
  /* 没有 BFC，子元素浮动后父元素高度塌陷为 0 */
}
.child {
  float: left;
  height: 100px;
}
</style>
<div class="parent">
  <div class="child">浮动元素</div>
</div>
<!-- 结果：parent 的 border 看起来只有一条线 -->
```

**BFC 解决方案：**
```css
.parent {
  border: 2px solid red;
  overflow: hidden; /* 触发 BFC，父元素高度恢复 */
}
```

#### 问题2：两个相邻元素的 margin 重叠

```html
<!-- 问题：两个 div 的 margin 重叠了 -->
<style>
.box1 { margin-bottom: 50px; }
.box2 { margin-top: 50px; }
/* 实际间距只有 50px，不是 100px */
</style>
```

**BFC 解决方案：**
```css
/* 把其中一个元素放进 BFC 容器 */
.wrapper {
  overflow: hidden; /* 触发 BFC */
}
```

#### 问题3：文字被浮动元素遮挡

```html
<!-- 问题：左边浮动图片，右边文字被压到图片下面 -->
<style>
.float-left {
  float: left;
  width: 200px;
}
.content {
  /* 文字会被浮动元素影响，可能显示在浮动元素下面 */
}
</style>
```

**BFC 解决方案：**
```css
.content {
  overflow: hidden; /* BFC 区域不会与浮动元素重叠，文字自动避开 */
}
```

### 总结一句话

**BFC = overflow: hidden**（这是最常用的触发方式，能解决浮动塌陷、margin重叠、浮动遮挡问题）。

## position 定位

| 值 | 特点 | 是否脱离文档流 | 参照物 |
|---|------|---------------|-------|
| static | 默认值，正常布局 | ❌ | 无 |
| relative | 相对定位，偏移自身位置 | ❌ | 自身原位置 |
| absolute | 绝对定位 | ✅ | 最近定位祖先 |
| fixed | 固定定位 | ✅ | 视窗 |
| sticky | 粘性定位 | ❌→✅ | 滚动容器 |

```css
/* 固定在底部 */
.footer {
  position: fixed;
  bottom: 0;
  left: 0;
  width: 100%;
}

/* 粘性导航 */
.nav {
  position: sticky;
  top: 0;
}
```

## 重排（Reflow）vs 重绘（Repaint）

### 重排（Reflow）
元素的位置、尺寸发生变化，需要重新计算布局。

触发重排的操作:
- 添加/删除可见 DOM 元素
- 元素尺寸变化（width、height、padding、margin、border）
- 内容变化（文本数量、字体大小）
- 浏览器窗口尺寸变化
- 读取某些属性：offsetWidth、scrollTop、clientTop 等

### 重绘（Repaint）
元素的外观发生变化，但尺寸不变。

触发重绘的操作：
- color、background-color
- visibility
- outline、border-color（不影响尺寸时）

### 性能优化建议

#### 1. 减少重排

| 做法 | 原因 | 示例 |
|-----|------|-----|
| 批量修改样式 | 避免多次触发重排 | 改 class 代替逐个改 style |
| 批量修改 DOM | 减少 DOM 操作次数 | 用 documentFragment |
| 动画元素脱离文档流 | 动画不影响其他元素 | 设置 absolute/fixed |
| 读写分离 | 避免强制同步布局 | 先读完再写，不要交替 |

```js
// ❌ 错误：读写交替，触发多次重排
for (let i = 0; i < 10; i++) {
  el.style.width = el.offsetWidth + 10 + 'px'; // 每次循环都重排
}

// ✅ 正确：先读完，再一次性写
const width = el.offsetWidth; // 只触发一次
for (let i = 0; i < 10; i++) {
  el.style.width = width + i * 10 + 'px';
}
```

```js
// ❌ 错误：逐个插入 DOM
for (let i = 0; i < 100; i++) {
  list.appendChild(document.createElement('li'));
}

// ✅ 正确：用 documentFragment 批量插入
const fragment = document.createDocumentFragment();
for (let i = 0; i < 100; i++) {
  fragment.appendChild(document.createElement('li'));
}
list.appendChild(fragment); // 只触发一次重排
```

#### 2. 减少重绘

| 做法 | 原因 |
|-----|------|
| 用 opacity/transform 做动画 | 这些属性不触发重排 |
| 避免频繁改动 color/background | 会触发重绘 |

#### 3. 利用 GPU 加速

```css
/* 动画元素开启 GPU 加速 */
.animate {
  will-change: transform;  /* 提前告知浏览器会变化 */
  transform: translateZ(0); /* 强制 GPU 渲染 */
}

/* 注意：不要滥用 will-change，会增加内存占用 */
```

#### 总结：性能优化核心原则

```
重排 > 重绘 > GPU合成
（性能消耗从大到小）

优先级：
1. 能用 GPU 合成 → 不触发重排重绘（最佳）
2. 只触发重绘 → 避免重排
3. 必须重排 → 批量处理，减少次数
```

## GPU 加速

使用 GPU 渲染元素，减少 CPU 负担。

### 触发 GPU 加速的属性
- `transform: translateZ(0)` 或 `transform: translate3d(0, 0, 0)`
- `will-change: transform`

## 响应式布局单位

| 单位 | 说明 |
|-----|------|
| rem | 相对于根元素 font-size |
| vw | 视窗宽度的 1% |
| vh | 视窗高度的 1% |
| % | 相对于父元素 |

### rem 方案
```css
html {
  font-size: 16px; /* 基准 */
}
.element {
  width: 10rem; /* = 160px */
}

/* 响应式调整 */
@media (max-width: 750px) {
  html { font-size: 14px; }
}
```

### vw 方案（移动端推荐）
```css
/* 1vw = 视窗宽度的 1% */
/* 750px 设计稿：1vw = 7.5px */
.element {
  width: 100vw;
  height: 50vh;
}
```

### 2.SVG与Canvas区别
+ SVG是基于XML的，可以操作DOM，渲染速度较慢

+ SVG适用于描述XML中的2D图形的语言,SVG更适合用来做动态交互，而且SVG绘图很容易编辑，只需要增加或移除相应的元素就可以了。

+ 在SVG中每个形状都被当做是一个对象，如果SVG发生改变，页面就会发生重绘

svg
1. 不依赖分辨率
2. 支持事件处理器
3. 最适合带有大型渲染区域的应用程序（比如谷歌地图）
4. 复杂度高会减慢渲染速度（任何过度使用 DOM 的应用都不快）
5. 不适合游戏应用

与其他图像格式相比，SVG的优势在于：
```
1. SVG矢量图，而canvas 依赖于分辨率。 所以svg 放大不会失真，但是canvas 绘制的图形会失真。很适合做地图，但是我看百度地图是canvas,高德是svg。
2. SVG图像可通过文本编译器来创建和修改
2. canvas 绘制的图形，只能给 canvas 整个画布添加事件，而不能给某个图形或文件添加事件处理器，但是 svg 支持事件绑定，如果需要添加带有事件的动画效果时，就需要选择 svg。
```

### Canvas（翻译为画布）是HTML5的一个标签，Canvas提供了给JavaScript在浏览器内绘制的能力
* 通过Javascript来绘制2D图形。
+ 比较新的技术,Canvas随时随地绘制2D图形（使用javaScript）,Canvas 提供的绘图能力更底层，适合做到像素级的图形处理，能动态渲染和绘制大数据量的图形。

+ Canvas是一像素一像素地渲染，如果改变某一个位置，整个画布会重绘。
```
1. canvas 适合图像密集型的游戏，频繁地重绘图像，svg 绘制的复杂度高时减慢渲染的速度。

2. 小画布、大数据量的场景适合用 Canvas，譬如热力图、大数据量的散点图等。如果画布非常大，有缩放、平移等高频的交互，或者移动端对内存占用量非常敏感等场景，可以使用 SVG 的方案。
```

Canvas
1. 依赖分辨率
2. 不支持事件处理器
3. 弱的文本渲染能力
4. 能够以 .png 或 .jpg 格式保存结果图像
5. 最适合图像密集型的游戏，其中的许多对象会被频繁重绘

### 3.WebSocket
WebSocket协议为web应用程序客户端和服务端之间提供了一种全双工通信机制。
+ 握手阶段采用HTTP协议，默认端口是80和443

+ 建立在TCP协议基础之上，和http协议同属于应用层

+ 可以发送文本，也可以发送二进制数据。

+ 没有同源限制，客户端可以与任意服务器通信。

+ 协议标识符是ws（如果加密，为wss），如ws://localhost:8023

## object-fit
* fill: 中文释义“填充”。默认值。替换内容拉伸填满整个contentbox,不保证保持原有的比例。
* contain: 中文释义“包含”。保持原有尺寸比例。保证替换内容尺寸一定可以在容器里面放得下。因此，此参数可能会在容器内留下空白。
* cover: 中文释义“覆盖”。保持原有尺寸比例。保证替换内容尺寸一定大于容器尺寸，宽度和高度至少有一个和容器一致。因此，此参数可能会让替换内容（如图片）部分区域不可见（上面讲解的例子就是如此）。
* none: 中文释义“无”。保持原有尺寸比例。同时保持替换内容原始尺寸大小。
* scale-down: 中文释义“降低”。就好像依次设置了none或contain, 最终呈现的是尺寸比较小的那个。

## 伪类-伪元素
* 伪元素： befor after 是元素，只不过不在dom里面，为了使css拿到dom元素以外得元素。
```
::after
::before
::firstLetter
::firstLine
::selection
```
* 伪类：伪类目的是拿到元素得状态

链接伪类(意:link，:visited，:target是作用于链接元素的！)
		:link		表示作为超链接，并指向一个未访问的地址的所有锚
		:visited	表示作为超链接，并指向一个已访问的地址的所有锚
		:target 	代表一个特殊的元素，它的id是URI的片段标识符

动态伪类(注意:hover，:active基本可以作用于所有的元素！)
		:hover		表示悬浮到元素上
		:active		表示匹配被用户激活的元素（点击按住时）
		
		由于a标签的:link和:visited可以覆盖了所有a标签的状态，所以当:link，:visited，:hover，:active同时出现在a标签
		身上时 :link和:visited不能放在最后！！！
		
		隐私:visited选择器
			只有下列的属性才能被应用到已访问链接：
				color
				background-color
				border-color

表单相关伪类
		:enabled	匹配可编辑的表单
		:disable	匹配被禁用的表单
		:checked	匹配被选中的表单
		:focus		匹配获焦的表单
