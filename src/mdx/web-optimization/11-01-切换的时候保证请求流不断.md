 关键是让请求独立于 React 组件生命周期。

  现在请求放在 PortfolioAnalyzerAi 的 useEffect 中，清理函数会调用 controller.abort()，所以关闭面板或切换页面就会中断。

  我会把它改成：

  - 共享会话管理器负责请求：持有 AbortController、运行中的 Promise 和分析状态，按组合 ID 保存。
  - 组件只负责展示和订阅：卸载时仅取消状态订阅，不调用 abort()；流事件继续更新共享状态。
  - 回来直接读取现有会话：恢复进度和报告。“开始分析”按钮读取同一份 generating，因此仍显示“分析中…”且不可点，也不会重新发请求。
  - 只有点击“停止”才主动 abort；刷新页面时，内存会话和当前连接随页面一起销毁。

  这里的“切换页面”指应用内的 Next.js 路由切换。整页跳转或刷新会销毁当前页面的 JavaScript 环境，符合你说的刷新后销毁。
